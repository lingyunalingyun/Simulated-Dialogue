# 模拟对话 skill（PersonaChat 专用蒸馏器）

读真实聊天记录 → 蒸馏成 **lean 人设档案**，喂给 PersonaChat 程序（`org.example.personachat`，
一个让两套人设各跑一个 LLM 实例互相私聊的 JavaFX 桌面程序）。

## 为什么不用 create-ex
create-ex 产出给人读的「关系档案」（关系记忆 + 5 层人物 + 分手档案 + 自带 Correction），200+ 行、
定位「前任刚分手」，塞进 PersonaChat 的 system prompt 后**和程序打架**。本 skill 产出**只剩纯人设**。

## 程序已包办，蒸馏档案里 ❌ 别重复写
程序 `Persona.buildSystem()` 运行时已自动加下面这些：

| 程序运行时已加 | 档案里 ❌ 不要写 |
|---|---|
| 「你就是 X 本人，正在和 Y 私聊」 | 身份扮演框架、"你是X不是AI" |
| 每句生成前检索真实语料片段注入 | 大段静态「关系记忆」流水账 |
| 外部 `data/corrections_*.json` 纠正 | skill 内自带的「Correction 记录」段 |
| 【心理】【消息】【离开】输出格式 | 任何输出格式 / json 规则 |
| 当前模拟时间（深夜/早上/饭点）注入 | 关系时间线表格、"现在是几点" |

> 注意区分：**程序注入的是"当前几点"**，而下面要蒸馏的**「作息」是这个人自己的生物钟**
> （几点睡几点醒），程序没有，必须写——这样角色才知道"到我点该困了"。

## 一、蒸馏维度（读语料后要总结的，每个都喂程序某机制）

**驱动程序时间线/事件的（重点挖）：**
- **作息时间**：几点睡、几点醒、深夜活跃区间
- **聊天节奏**：一次能聊多久、回复多快、谁先开头、什么场景断（→ 开场方、"晚安死循环"收尾）
- **日常活动/要做的事**：打游戏、洗澡、上课、画图…（→ 喂程序「离开」事件）
- **兴趣爱好**：会主动聊起的话题
- **发图时机**：什么情绪/话题下爱发图（→ 输出 `【一张xxx的图片】` 占位）
- **发表情时机**：什么时候甩表情包（→ 输出 `【表情:label】`，真发）
- **语音习惯**：什么时候发语音、长语音还是短语音（→ 输出 `【一段xxx的语音】` 占位，语音生成系统以后做）
- **事件种类**：ta 会做的事的"种类"清单——打游戏/出门/剪头发/转账/上课/买东西/生病…（→ 喂「离开」事件和话题。**完整事件全集另理 `events.md`，不进 lean 人设**，见第四节）

**塑造人设的：**
- **性格底色**（两边都做：读语料时分清"用户本人"和"对方"两个 accountName）
- **说话风格**：口头禅、语气词、标点、emoji、句长与连发习惯、真实原句
- **情感模式**：开心 / 不对劲 / 撒娇 / 吃醋 / 受伤 各怎么表现 + 触发器
- **关系行为**：在关系里的角色、主动程度、边界底线
- **inside jokes & 专属称呼**
- **别做（OOC 禁忌）**

## 二、产出格式：lean 人设模板
蒸馏的唯一目标是填满下面模板。每节要能直接转成「演」的指令，不要写给人看的长篇分析。

> 📏 **详细度要求**：lean = 砍掉"程序已包办的冗余"，**不是写得少**。
> 每份档案必须**非常详细、不少于 300 字**：每节都填实、多带真实原句、把口头禅/情绪/触发器写具体，越细越还原。

```markdown
# {显示名}（{真名或代号}）

> {一句话身份：年龄/身份/和对方是什么关系（写事实，不写"此刻处在哪个阶段"——当前关系/时间线定位由软件的「当前关系」栏管理）}

## 作息与节奏
- 作息：{几点睡、几点醒、深夜活跃区间}
- 聊天节奏：{一次聊多久、回复快慢、谁先开头、什么时候断}
- 日常要做的事：{打游戏/上课/洗澡/画图… 这些会让 ta 说"我去X了"暂时离开}
- 兴趣/会主动聊的话题：{……}

## 说话风格（占比最大）
- 口头禅：`原句` — 什么时候说（每条带真实原句）
- 语气词 / 标点 / emoji 习惯：{频率，什么情绪下才爆发}
- 句长与连发：{……}
- 真实原句示例（5–8 条，挑最像 ta 的）：
  - `……`

## 发图 / 表情 / 语音习惯
- 发图：{什么情绪/话题爱发图} → 想发图时输出一行 `【一张xxx的图片】`（如 `【一张刚抽到角色的截图】`）
- 表情包：{什么时候甩表情、爱用什么调性的} → 想发表情时输出一行 `【表情:label】`（label 用情绪词，如 `【表情:笑哭】`）
- 语音：{什么时候发语音、长短} → 想发语音时输出一行 `【一段xxx的语音】`（如 `【一段哼歌的语音】`）

## 会做的事（事件种类）
- {打游戏/出门/剪头发/转账/上课/买东西… 这些"种类"喂「离开」事件和话题；完整事件全集在 events.md，不写这}

## 情感模式
- 性格底色一句话：{……}
- 开心：…… ｜ 不对劲：…… ｜ 撒娇：…… ｜ 吃醋/在意：…… ｜ 受伤：……
- 触发器：{什么场景触发上面哪种}
- 爱的语言：{……}

## 关系行为
- 在关系里的角色 / 主动程度 / 边界底线

## 必备事实 & inside jokes（演得像所需的最少量，宁缺勿滥）
- 专属称呼：ta 叫你「…」，你叫 ta「…」
- 3–6 条核心共同记忆 / 梗（程序会再检索语料，这里只放高频核心的）

## 关键时间（事实锚点，供软件「当前关系」栏参考）
- 认识：{什么时候、怎么认识的}
- 确定关系：{大概什么时候在一起}
- 重要节点：{异地/纪念日/分开… 带日期或时长的事实；只写事实，不写"现在处在哪"}

## 别做（防 OOC）
- 不突然变完美 / 不无条件包容（除非 ta 本来如此）
- 不说 ta 现实里绝不会说的话
- {针对这个人的具体禁忌}
```

> ⚠️ **当前关系/时间线定位由软件管理**，skill 不写"此刻处在哪个阶段"。
> PersonaChat 软件有常驻的「当前关系」栏（可手动改、生成时注入双方 prompt）。
> skill 只在档案里记**关键时间(事实锚点)** 供软件参考。这是和旧 create-ex 档案最大区别。

## 三、工作流

### Step 1　命名
**本 skill 的根本工作方式：一份聊天记录 → 同时分出双方两份人设档案**（不是二选一）。
读语料时按两个 `accountName` 拆出"用户本人"和"对方"，各产出一份。
只需问用户两人各自的新 skill id（建议 `{slug}_sim`，不覆盖原有人设）。
**时间线定位不要问**——「一句话定位」那行留给用户自己填（也可留空），skill 不替他决定走 what-if 还是刚分手。

### Step 2　取语料（复用，不重造；中文路径走管道避免编码坑）
聊天记录建议用 WeFlow / WeChatMsg / 留痕 等工具导出成 jsonl，路径形如
`{你的聊天记录导出目录}/texts/{对方}.jsonl`（`type=0` 文字；`accountName` 区分双方；图片 type7、引用 type25、撤回 type80）。
按维度抽样统计，例如某人作息分布（把路径和 accountName 换成你自己的）：
```bash
cat "{你的导出目录}/texts/{对方}.jsonl" | python3 -c "
import sys,json,collections,datetime
h=collections.Counter()
for line in sys.stdin:
    try:o=json.loads(line)
    except:continue
    if o.get('type')==0 and o.get('accountName')=='{对方accountName}':
        h[datetime.datetime.fromtimestamp(o['timestamp']).hour]+=1
print(sorted(h.items()))"
```
口头禅/原句/各情绪句子用 `Grep` 或 python 抽样。要解析新导出文件，可复用 create-ex 系的
`wechat_parser.py` 之类工具。

### Step 3　蒸馏 → 预览
按模板填写。向用户展示**摘要**（每节 2–3 行）确认，**不要一次性甩文件**。逐节核对，尤其「定位/别做」符合 Step 1。

### Step 4　导出 + 在软件里导入（不再改代码）
1. `Write` 双方人设各一份 `.md`（如 `~/.claude/skills/{slug}_sim/SKILL.md`）。
2. **不要再改 `App.java`**。告诉用户在 PersonaChat 软件里点「**导入对方人设 / 导入我方人设**」，选这两个 `.md`——
   软件会把它们**复制进自己的 `data/personas/`**（之后在软件里改、不动原文件）。这就是 skill 与软件的贴合点。
3. 时间线 / 当前关系在软件的「**当前关系**」栏里设（可手动改），skill 不管。

## 四、图片 / 表情 / 语音 / 事件（跨程序，分阶段）
- **图片**：不真发。想发图 → 输出 `【一张xxx的图片】`，程序当图片气泡显示文字。生图接口以后做。
- **语音**：不真发。想发语音 → 输出 `【一段xxx的语音】`，程序当语音气泡显示文字。语音生成系统以后做。
  （导出目录下的 `voices/` 留着将来用。）
- **表情包**：**真发**。素材在导出目录的 `emojis/`（若干张 gif/png，多为 md5 命名）。
  ⚠ 注意：文本 jsonl 通常**不含表情的 md5 链接、无频次** → 表情库靠**视觉聚类去近重 → 选代表 → 打情绪标签**（采样常用的）。
  模型输出 `【表情:label】`，程序按 label 映射到表情文件并在 UI 渲染 gif/png。
- **事件全集**：Claude 按本 skill 把聊天里出现过的事件**尽量全面**理成单独文件
  `~/.claude/skills/{slug}_sim/events.md`（转账/红包、出门、剪头发、考试、买东西、生病、约会、吵架…）。
  **不进 SKILL.md**（否则每次注入稀释人设），留给将来「事件系统」按需检索。

**程序侧改动（单独做，分阶段）：**
- P2：解析 `【一张…】`/`【一段…语音】`/`【表情:…】` 标记 → UI 各自渲染（图片/语音先文字气泡）
- P3：表情库 label→文件映射、UI 渲染真 gif/png、把可用表情 label 清单注入模型
- P4：事件系统——程序按需检索 events.md（像检索语料那样）；以后接生图 / 语音生成接口

## 五、纠正 / 进化
PersonaChat **已有运行时纠正**：界面点气泡 ✗ → 写说明 → 进 `data/corrections_{...}.json`，下批生效。
**日常细节纠正走程序，别往人设文件塞 Correction 段。**
只有"人设根子写错/漏了"（说话风格判断错、定位选错、核心事实缺失）才回来用本 skill 重蒸馏或 `Edit` 修订对应小节，保持精简。

## 隐私
本 skill 处理的是私人聊天记录。所有原始数据与蒸馏出的个人人设**仅本地存储，不要上传**。
本仓库发布的是**通用工具本体**，不含任何真人数据。
